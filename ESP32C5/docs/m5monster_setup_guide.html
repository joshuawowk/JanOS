M5MonsterC5 Setup Guide

Build the dual-band Wi-Fi + sub-GHz add-on for the M5Stack Tab5 — wire the ESP32-C5 and a CC1101 radio, flash both halves of the firmware, and confirm it live. Works with the store-bought M5MonsterC5 board or a DIY ESP32-C5 dev board.

01

How the stack fits together

Three parts, one wire harness. The Tab5 is only a screen and keyboard; every radio operation runs on the ESP32-C5 (firmware: JanOS), and the CC1101 gives that C5 its sub-GHz teeth. They talk over a plain serial link.

i

Buy or build? The $75 M5MonsterC5 board is the ESP32-C5 pre-mounted with the Grove/M5Bus connectors, an SD slot and a GPS port — plug-and-play. A DIY ESP32-C5-DevKitC-1 (~$15) does the same electrically; you add the CC1101 and (optionally) a microSD breakout with a few jumpers. This guide covers both — the wiring below is identical, the store board just pre-makes the Tab5 connection.

02

What you need

Minimum is an ESP32-C5 and the Tab5. Add the CC1101 for sub-GHz, an SD card for capture storage and captive portals, and GPS for wardriving.

required

ESP32-C5 board

M5MonsterC5, or an ESP32-C5-DevKitC-1. Must be the C5 — it is the only ESP32 with 2.4 and 5 GHz Wi-Fi.

required

M5Stack Tab5

ESP32-P4 tablet. Runs the M5MonsterC5-Tab5 UI app.

sub-GHz

CC1101 module

Any 3.3 V CC1101 breakout (E07-M1101D and clones). Needs SCK/MOSI/MISO/CSN/GDO0 broken out.

storage

microSD + breakout

On the store board it's built in. For DIY, a 3.3 V SPI microSD breakout on the shared bus.

optional

GPS module

ATGM336H (9600) or M5Stack GPS v1.1 (115200) for wardrive location.

glue

Jumpers + Grove cable

Dupont wires for the CC1101, and one Grove cable for the Tab5 link (DIY route).

03

Wiring

Two harnesses: a 4-wire UART from the Tab5 to the C5, and the CC1101 on the C5's SPI2 bus (the same bus the SD card uses — each device just gets its own chip-select). All logic is 3.3 V.

Prefer the M5Bus port? Use Tab5 GPIO37 (TX) / GPIO38 (RX) instead — the app auto-detects the C5 on whichever port answers.

Change these defaults, if you must, in components/cc1101/include/cc1101.h (CC1101_PIN_CS / GDO0 / GDO2).

✕

Do not use these pins for the CC1101. GPIO15–22 are the C5's in-package flash + Quad-PSRAM bus (touching them bricks the boot). GPIO3/4 belong to the nRF24 driver. GPIO11/12 are the console UART the Tab5 depends on. Strapping pins 2 · 7 · 27 · 28 are already committed. GPIO 5/23/24 were chosen precisely because they dodge all of these.

Optional: microSD & GPS pins
PeripheralSignal → C5 pin
microSD (SPI2)MISO G2 · MOSI G7 · CLK G6 · CS G10
GPS (UART1)TX G13 · RX G14

SD shares the same three SPI2 lines as the CC1101 with its own CS (GPIO10) — both live on the bus at once. GPS is its own UART.

04

Flash the firmware

Two independent images: JanOS on the ESP32-C5 and the M5MonsterC5-Tab5 app on the Tab5. Do the C5 first so it's ready when the Tab5 comes up. The web flashers need Chrome/Edge (WebSerial).

1

Flash JanOS onto the ESP32-C5

Easiest — the web flasher. Plug the C5 into USB, open the flasher, pick the port, flash.

# web flasher (Chrome/Edge) → https://c5lab.github.io/projectZero/janos_flash.html

Or build this SubGHz-enabled tree from source with ESP-IDF v5.4.x and flash over USB:

# from JanOS/ESP32C5 $ . $IDF_PATH/export.sh $ idf.py set-target esp32c5 # already set $ idf.py build $ idf.py -p /dev/ttyACM0 flash monitor

Raw esptool offsets, if you prefer them (from the build output):

$ python -m esptool --chip esp32c5 -b 460800 write_flash \ --flash_mode dio --flash_size 8MB --flash_freq 80m \ 0x2000 build/bootloader/bootloader.bin \ 0x8000 build/partition_table/partition-table.bin \ 0xf000 build/ota_data_initial.bin \ 0x20000 build/projectZero.bin
2

Flash the app onto the Tab5

Same idea on the ESP32-P4 side.

# web flasher (Chrome/Edge) → https://c5lab.github.io/M5MonsterC5-Tab5/janos_flash.html

Or with esptool (ESP32-P4): bootloader 0x2000, partition-table 0x8000, app 0x10000.

$ python -m esptool --chip esp32p4 -b 460800 write_flash \ 0x2000 bootloader.bin \ 0x8000 partition-table.bin \ 0x10000 M5MonsterC5-Tab5.bin
3

Power up together

With the harness connected, boot the Tab5. It probes the Grove/M5Bus port, finds the C5, and reads its firmware version.

!

Version lock. The Tab5 app requires JanOS 1.7.1 exactly (JANOS_VERSION_REQUIRED). A mismatch shows a "firmware too old/wrong" popup and disables features. The tree in this repo already reports 1.7.1 — if you flashed an older release, update JanOS.

05

Verify & use the sub-GHz suite

Open the SubGHz tab on the Tab5. The first radio action asks the C5 to init the CC1101; the radio badge turns to OK on success (or NONE if the CC1101 isn't answering).

badge CC1101 initialized or CC1101 NOT DETECTED

Every screen maps to a console command the C5 now implements. Quick smoke test: open Listen at 433.92 MHz and press a cheap remote near the antenna — a captured signal row should appear.

06

Bench-tuning & coverage

The firmware compiles clean and speaks the protocol exactly, but the RF constants ship as sensible defaults — they were not tuned against a live radio. Budget one bench session.

  • RF timing constants — RX bandwidth, data rate, glitch/idle thresholds and the TX inter-frame gap live in cc1101.c / subghz_capture.c. Adjust against a known remote.
  • Decoders — Princeton / PT2262 / EV1527 fixed-code remotes decode to serial + button. Anything else is captured as Unknown but still saves and replays (Flipper RAW-style).
  • Weather — the Nexus-TH family decodes; the framework in subghz_decode.c is built to add Acurite / LaCrosse / etc.
  • Rolling codes — KeeLoq and friends cannot be cloned; they're reported, not replayed.
!

Transmit responsibly. Jammer and replay actively transmit. Know your local rules, use only on hardware you own, and keep power low on the bench.

Symptom → check
SymptomLikely cause / fix

Nothing captured in ListenAntenna missing, wrong band, or RSSI floor too high. Set the floor to −85 and press a remote up close.
